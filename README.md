# 🏠 Логические сценарии для SprutHub

Коллекция логических сценариев для платформы умного дома **[Sprut Hub](https://spruthub.ru)**. Все сценарии написаны на JavaScript, протестированы в реальных условиях и развиваются итеративно — с детальным логированием, понятными настройками и историей версий.

### Как сценарии связаны

Итоговый датчик присутствия жильца, который ведёт **«Присутствие жильца»**, служит основой режима «Не дома». От него зависят другие сценарии:

- **«Видеонаблюдение»** включает камеры в режиме «Не дома» и выключает их после прихода жильца;
- **«Окно — проветривание»** не открывает окно в режиме «Не дома» и при присутствии людей в комнате;
- **«Время присутствия»** считает время пребывания по тому же датчику.

В итоговый датчик должен писать только один сценарий, остальные его только читают.

## ⚙️ Общие требования

- **Sprut Hub** с поддержкой логических сценариев
- Устройства, интегрированные через стандартные HomeKit-сервисы (Thermostat, Fan, FilterMaintenance, CarbonDioxideSensor, AirQualitySensor, ContactSensor, OccupancySensor и т.д.)
- Для рекуператора — устройство **VAKIO BASE SMART**, подключённое по **MQTT**
- Для кондиционера — контроллер **Lytko**, подключённый по **MQTT**
- Для присутствия — итоговый датчик `HS.OccupancySensor` на каждого жильца (например, в виртуальном устройстве СХ) и хотя бы один сетевой источник; остальные источники (геозона, Homebridge, дверь, личная разблокировка, ping) повышают точность
- Для проветривания окном — привод окна с характеристикой «Целевая позиция» и хотя бы один источник качества воздуха (CO₂, VOC или индекс качества воздуха)
- Необязательно: глобальная функция `sendTG` для уведомлений в Telegram (используется в «Присутствии жильца» и «Окне — проветривании»)

## 🚀 Установка

Общий порядок для любого сценария:

1. Скачать `.json` сценария (и при необходимости — шаблон устройства) из соответствующей папки
2. В SprutHub → **Логика → Шаблоны** → импортировать
3. Привязать сценарий к нужному сервису или характеристике устройства
4. Заполнить настройки (см. README конкретной папки)
5. Включить сценарий

> Один экземпляр «Присутствия жильца», «Времени присутствия» и «Окна — проветривания» соответствует одному человеку или одному окну. Для каждого следующего добавляется отдельный экземпляр.

## 🛠️ Особенности платформы SprutHub, учтённые в коде

При разработке учтён ряд платформенных ограничений Nashorn/SprutHub:

- JS-движок — без стрелочных функций, без `String.prototype.padStart` и т.п.
- `variables` логического сценария **не персистентны** — обнуляются при перезапуске; для хранения используются характеристики устройства (`C_GasMeter` / `C_CubicMeter`, `C_Distance`)
- В `variables` вместо `undefined` может прийти `null` — значения нужно проверять на корректность, иначе возможны мусорные результаты
- `HC.FilterLifeLevel` — **read-only**, `setValue` не сохраняется между сессиями
- Поиск сервисов по имени ненадёжен — спецсимволы (`³`, скобки и др.) обрезаются при `getName()`, поэтому используется поиск по UUID
- `HS.FilterMaintenance` не может будить сценарий через `sourceServices`
- В UI SprutHub тип поля `"Number"` не поддерживается — нужно использовать `"Integer"` или `"Double"`
- Функции, использующие `options`, должны получать его явным параметром (иначе падает на старте/триггере)

## 📝 Логирование

В каждом сценарии есть переключатель **«Логирование событий»**, который включает информационные сообщения в лог. При выключенном логировании остаются только ошибки и критические предупреждения. В отдельных сценариях есть дополнительные переключатели для подробной диагностики (например, подробный лог ping в «Присутствии жильца»).
